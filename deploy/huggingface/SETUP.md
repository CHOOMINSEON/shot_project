# 새 주소로 테스트 배포

현재 작업 공간에서 Cloudflare 주소 발급 API는 차단 응답을 반환했고, Gradio 공개 연결도 세션 종료/EOF로 실패했습니다. 공개 주소는 발급·검증되지 않았습니다. 이 파일은 터널에 의존하지 않고 앱을 호스팅 서버에서 직접 실행하는 대안입니다.

## 계정·비용 조건부터 확인

2026-10-12에 확인한 [Hugging Face 공식 문서](https://huggingface.co/docs/hub/spaces-overview)는 CPU Basic(2 CPU·16GB RAM·50GB 비영속 디스크)의 시간당 비용은 없지만, **Docker 또는 Gradio Space 생성에는 유료 플랜이 필요**하다고 안내합니다. 따라서 무료 계정만으로 이 서버 앱을 무료 배포할 수 있다고 안내하지 않습니다. 이 작업에서 계정 가입·플랜 구매·과금 서비스 생성은 수행하지 않았습니다.

이미 해당 플랜을 사용하는 경우 다음 순서로 진행할 수 있습니다. 그렇지 않다면 요금에 동의하기 전에 결제를 진행하지 말고 사용할 호스팅부터 정하세요.

## 배포

1. Hugging Face에 로그인하고 [새 Space 만들기](https://huggingface.co/new-space)를 엽니다.
2. 이름을 정하고 SDK는 **Docker**로 선택합니다. CPU Basic을 선택하며 하드웨어·플랜 조건을 확인합니다. 공개 소스 저장소를 사용할 때 소유자 비밀번호나 촬영 원본을 파일로 올리지 않습니다.
3. `iyoring-cut-studio-huggingface.zip`을 컴퓨터에서 압축 해제합니다. ZIP 자체를 코드 파일 대신 업로드하지 말고, 압축 안의 `Dockerfile`, `README.md`, 코드 폴더 등을 Space 저장소의 루트에 올립니다. 원래 사이트 데이터는 이동하지 않습니다.
4. Space Settings의 **Variables and secrets**에서 **Secret** `STUDIO_PASSWORD`를 12자 이상으로 지정합니다. 그 비밀번호로 앱에 로그인합니다. 비밀번호를 공개 Variable이나 대화에 올리지 않습니다.
5. 빌드와 최초 모델 다운로드가 끝난 뒤 앱의 `…hf.space` 직접 주소를 새 탭으로 엽니다. Space 페이지의 내장 화면은 앱의 iframe 제한과 쿠키 정책 때문에 로그인에 적합하지 않습니다.
6. 짧은 샘플로 로그인 → 업로드 → 편집 → 자막 검수 → MP4/SRT 출력부터 확인합니다.

앱은 실제 서버에서 실행되지만 기본 저장소는 임시입니다. 모델 설치와 프로젝트 보존은 해당 Space의 저장소·수면/재시작 조건에 영향을 받습니다. 생성된 출력을 내려받아 보관하세요. 실제 고밀도 10GB·2시간 촬영 원본 부하와 이 플랫폼의 운영 조건은 계정에 배포한 뒤 별도로 확인해야 합니다.

## 이 작업의 상태

- 소스와 시작 설정을 준비했습니다.
- 사용자의 호스팅 계정은 연결되지 않았습니다.
- 공개 사이트 게시나 외부 접속 성공을 주장하지 않습니다.
