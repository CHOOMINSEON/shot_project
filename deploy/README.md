# 공개 서버 배포·수정·재배포

실제 서버나 호스팅 계정과 도메인이 연결되어야 공개 배포할 수 있습니다. 현재 작업 공간의 앱 실행이나 클라우드 설정 초안 저장은 공개 배포가 아닙니다. 이 문서의 명령은 배포할 운영 서버에서 실행합니다.

결제 없는 PC 실행 + 임시 공개 주소 패키지는 [free-local/README.md](free-local/README.md)를 참고하세요. 아래 구성은 별도 서버·도메인이 있는 경우 사용합니다.

## 준비

- Docker와 Docker Compose v2를 설치한 Linux 서버.
- 장시간 미디어 처리를 위해 4 vCPU·8GB RAM·100GB 이상 저장 공간을 권장합니다. 입력 파일당 10GB, 원본 2시간, 출력 영상당 30분은 별도 제한입니다.
- 실제 도메인의 DNS를 서버에 연결하고 TCP 80/443 포트를 열어 주세요. UDP 443은 HTTP/3 사용 시 선택 사항입니다.
- 다른 웹 서버가 이미 80/443 포트를 쓰는 경우 기존 HTTPS 프록시에 연결해야 합니다. 기존 서버를 임의로 중지하지 마세요.
- `.data`, 원본, 비밀번호를 소스 저장소나 공개 정적 사이트에 올리지 않습니다. 공개 사이트에서도 원본·프로젝트는 소유자 로그인으로 보호합니다.

## 첫 배포

```bash
cp deploy/production.env.example deploy/.env.production
chmod 600 deploy/.env.production
# 환경 파일에 실제 도메인, 고유한 릴리스 이름, 12자 이상의 소유자 비밀번호를 설정합니다.
bash deploy/publish.sh
```

`publish.sh`는 설정 검증 → 릴리스별 앱 이미지 빌드 → 앱 시작 및 건강 상태 확인 → 한국어 모델 설치 → Caddy HTTPS 시작 → 공개 HTTPS 주소에서 앱 이름/상태 확인을 수행합니다. 인증서 검증은 활성 상태로 유지합니다. 인증서 발급에는 실제 DNS와 외부에서 접근할 수 있는 80/443 포트가 필요합니다.

`production.yaml`의 앱 포트는 Docker 내부에서만 노출합니다. Caddy가 HTTPS 인증서·갱신과 HTTP→HTTPS 전환을 관리합니다. 소유자 비밀번호 값은 명령에 직접 넣거나 로그로 출력하지 마세요. 환경 파일에는 운영 서버의 안전한 설정 방식으로 값을 입력합니다.

서버 재시작 시 앱·프록시는 자동 시작하며, 원본·프로젝트·모델·출력은 `studio-data` 영속 볼륨을 사용합니다. 초기 배포는 빈 볼륨으로 시작합니다. 기존 작업 공간의 영상을 운영 서버로 자동 이동하지 않습니다.

## 피드백 반영 후 재배포

1. 수정한 소스를 운영 서버에 반영합니다.
2. `.env.production`의 `STUDIO_RELEASE`를 새 이름으로 변경합니다(예: `2026-10-13-fix1`). 이전 릴리스 이미지를 유지합니다.
3. `bash deploy/publish.sh`를 실행합니다.
4. 공개 주소에서 로그인, 기존 프로젝트, 업로드, 자막 검수, 짧은 영상 출력을 확인합니다.

같은 볼륨·비밀번호·도메인을 유지하므로 수정 배포 시 원본을 새로 올릴 필요가 없습니다. 원본·프로젝트의 백업은 운영 저장소에서 별도로 보관합니다.

## 이전 앱 버전으로 복원

```bash
bash deploy/rollback.sh 2026-10-12-gray
```

서버에 보관된 해당 릴리스 이미지를 재사용합니다. 원본 볼륨을 지우거나 앱을 다시 빌드하지 않습니다. 복원 후 공개 주소에서 로그인과 프로젝트를 확인하세요. 다음 배포에는 환경 파일의 릴리스 이름도 맞춰 주세요.

## 이 작업 공간의 검증 범위

Compose 설정과 Caddy HTTPS 구성을 검증했습니다. 신뢰할 수 있는 로컬 테스트 인증서로 실제 HTTPS 프록시를 거친 소유자 로그인·Secure/HttpOnly 쿠키·Origin 검증·청크 업로드·영상 Range 재생을 확인했습니다. 실제 운영 도메인에서의 인증서 발급과 인터넷 외부 접속은 배포 대상 연결 후 확인해야 합니다.
