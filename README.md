# 신상집착 컷 스튜디오

리뷰하는 이요링을 위한 새 자동 컷편집 앱입니다. FastAPI + SQLite + 디스크 기반 네이티브 FFmpeg와 한국어 브라우저 UI로 구현했습니다. 기존 Sites 앱을 수정·재배포한 결과가 아닙니다.

## 실행

Windows용 바로 실행 프로그램은 [desktop/README.md](desktop/README.md)에 안내합니다. GitHub Actions가 실제 Windows 테스트와 실행 파일 자체의 검증을 통과한 경우에만 Release에 `IyoringCutStudio.exe`를 게시합니다. Docker·Python·FFmpeg 별도 설치 없이 해당 PC에서 작업하며, 공개 웹사이트 배포와는 다릅니다.

**[Windows 바로 실행 파일 다운로드](https://github.com/CHOOMINSEON/shot_project/releases/download/desktop-windows-8642d963/IyoringCutStudio.exe)** — Windows 10/11 x64용, 약 281MB. 기존 실행 창을 닫은 뒤 새 파일을 더블클릭하세요. 브라우저와 작업실을 먼저 열고, medium 모델 약 1.5GB는 배경에서 자동 준비합니다. 상단에서 받은 파일 크기·준비 상태·실패 시 재시도를 확인할 수 있습니다. 준비 중에도 영상 업로드·무음 자동 컷편집·기획·수동 컷 편집을 사용할 수 있습니다. 작업하는 동안 실행 창을 켜두세요. 결제·회원 가입·별도 개발 도구 설치는 필요하지 않습니다. 브라우저가 보이지 않으면 실행 창의 **접속 주소:** 뒤에 나오는 주소를 Chrome/Edge에 붙여 넣으세요(이 PC에서 10분 동안 한 번 사용).

결제 없이 사용자 PC에서 실행하고 임시 공개 주소를 만드는 패키지는 [deploy/free-local/README.md](deploy/free-local/README.md)를 참고하세요. 공개 접속은 PC·Docker·인터넷과 터널 연결이 유지되는 동안 가능합니다. 현재 클라우드 환경에서는 공개 터널 연결이 실패했고 공개 배포는 완료하지 못했습니다.

Python 3.12, FFmpeg/ffprobe, libx264/AAC/zscale 필터가 필요합니다.

```bash
bash scripts/install.sh
bash scripts/start.sh
```

서버는 기본적으로 로컬의 8000 포트에서 실행합니다. `STUDIO_HOST`와 `STUDIO_PORT`로 변경할 수 있습니다. 로컬 소유자 비밀번호는 첫 시작 시 `.data/owner-password`에 생성되며 화면·로그에 출력하지 않습니다. 운영 환경에서는 12자 이상의 `STUDIO_PASSWORD`를 환경 설정에 안전하게 넣으세요. 비밀번호를 Git에 커밋하지 마세요. 외부 접속은 HTTPS reverse proxy를 사용해야 브라우저 청크 검증이 동작합니다.

설치 스크립트는 정확도를 우선해 **Whisper medium / CPU int8** 모델을 다운로드합니다(약 1.5GB). 사용자 영상·오디오는 모델 호스트나 외부 음성 인식 API로 보내지 않고 앱 서버에서 처리합니다. 한국어 고유명사·가격·점수·부정 표현은 원음 검수가 필요합니다. CPU 처리 시간·메모리가 중요하면 `STUDIO_WHISPER_MODEL=small bash scripts/install.sh`와 `STUDIO_WHISPER_MODEL=small bash scripts/start.sh`로 small을 선택할 수 있습니다. 모델 파일은 이름별 디렉터리에 검증 후 이동하므로 기존 모델을 덮어쓰지 않습니다. 모델을 바꿀 때 서버를 재시작하세요. 이미 대기 중인 인식 작업과 체크포인트는 원래 모델을 유지합니다. 음성 모델이 없어도 장면·OCR 검색, 기획·수동 편집은 가능합니다. 장면·OCR 모델 약 172MB는 첫 검색·무음 컷에서 검증 후 자동 다운로드합니다.

## 예상 대본·연출로 자동 편집

촬영 영상을 올리고 **예상 대본**과 **연출 메모**만 입력한 뒤 **대본대로 자동 편집 시작**을 누릅니다. 실제 대사를 인식하고 입력 대본의 순서로 연결하며 미리보기까지 생성합니다. 직접 녹음한 WAV/MP3/M4A 등 더빙을 추가하면 해당 음성을 우선 사용하고 나머지는 촬영 원음에서 찾아 한 편 안에서 섞습니다. 기본 CU 대본의 대괄호는 실제 제품명·맛 평가·결론으로 채워 주세요. 빈칸/미일치 대사는 표시하고 부분 미리보기와 완성본을 구분합니다.

빠른 템포·9:16·첫 문장 중앙 확대·흐린 배경을 연출 메모로 적용합니다. 같은 원본 대사가 있으면 더빙 화면을 연결하고, 없으면 영상 장면 후보를 원본으로 확인한 뒤 선택합니다. 업로드 순서나 파일명만으로 화면을 확정하지 않습니다. 얼굴 추적/효과음/음악 생성은 포함하지 않습니다. 미지원 지시는 결과에서 표시하고 입력 대본은 그대로 보존합니다. 자세한 PC 사용법은 [desktop/README.md](desktop/README.md)를 참고하세요. 기존 세부 기획·자막 도구는 **세부 편집** 메뉴에 있습니다.


## 대본 기반 영상 장면 검색

기존 검색은 Whisper 전사와 문자열 유사도만 사용했고 프레임 분석/OCR/장면 인덱스가 없었습니다. 실제 작업 큐에 로컬 CLIP ViT-B/32와 한국어 PaddleOCR를 연결했습니다. 유료 API를 호출하거나 프레임을 외부로 전송하지 않습니다. `studio/scene_index.py`의 영어 문구가 실제 CLIP 입력이며, `studio/scene_search.py`의 한국어 규칙으로 제품·종류·행동·시각 특징·추상 의미·역할을 추출합니다. 사전에 없는 표현은 자동 의미 일치를 확정하지 않습니다.

- 원음 대사 검색과 영상 장면 검색을 함께 수행합니다. 말이 없어도 실제 PTS에 연결된 프레임을 검색하고 파일명, 시작/종료, OCR, 이유, 불확실성을 반환합니다. 장면 전환을 프레임마다 확인하고 기본 1초, 전환·새 제품 문구/행동 주변 0.5초 간격으로 추론합니다. 순간 노출은 여전히 놓칠 수 있습니다.
- 왼쪽 **제품 이름·참고 이미지 등록**에서 제품명·종류·브랜드·맛·별칭·포장 특징·이미지를 선택적으로 입력합니다. OCR·참고 이미지·같은 연속 숏의 근접 문맥을 결합합니다. 색상만으로 식별하지 않으며 다른 맛은 별도 제품으로 등록합니다. 연속성만 있는 후보는 확인 필요입니다. 반복되는 작은 모서리 문구는 워터마크 후보로 제외합니다.
- **대사 일치 / 제품 일치 / 의미 일치 / 보조 장면 / 확인 필요**를 구분합니다. 시각 모델 점수는 정확도 확률이 아닙니다. 내용물의 양·맛·감정·재구매는 표정으로 단정하지 않습니다. 정확한 근거가 없으면 **정확한 일치 없음**과 보조 후보를 분리합니다.
- **원본 구간 재생 → 원본 확인 후 이 장면 선택**으로 대본 순서에 연결합니다. 보조 후보는 **보조 장면으로 사용**을 명시합니다. 대본을 인식 자막이나 합성 음성으로 만들지 않습니다. 선택 뒤 기존 수동 컷 도구로 경계를 조정할 수 있습니다.
- 더빙이 장면보다 길면 선택 구간의 마지막 프레임을 유지합니다. 선택 장면 밖의 다른 영상을 반복하지 않습니다. 컷·순서 변경 시 기존 수정 자막도 원본 시간으로 다시 연결하며 검수는 다시 필요합니다.
- **최종 편집본 다운로드**는 최종 MP4가 없으면 생성하고 완료 후 다운로드를 시작합니다. 이전 컷의 출력은 자동 다운로드하지 않습니다. 미정 대본·미검수 자막은 먼저 확인해야 합니다.

## 선택 메뉴: 지침에 따른 푸드 숏폼 기획

1. **숏폼 기획** 탭에 소재·질문·실제 평가·고른 이유·평가 기준·촬영 가능 컷·제작 조건을 입력합니다. 외부 자료는 URL·기준일·용량/수량/할인/배송 조건을 기록합니다. 사용자 제공 사실, 외부 자료, 가정을 구분합니다.
2. **기획 초안 만들기**를 누르면 아래 기획 보드에 소재, 3가지 후킹, 구성안, 6줄 요약, 썸네일 3개/제목 5개, 게시 캡션을 순서대로 표시합니다. 각 항목의 5개 기준을 0/1/2점으로 합산하고 잠정 점수·감점·개선안을 표시합니다. 단일 제품 18초, 비교·리스트 60초, 조리 30초가 기본이며 직접 지정한 길이를 우선합니다.
3. 결과는 **지침 기반 템플릿 초안**입니다. 생성형 AI나 웹 검색을 호출하지 않습니다. 외부 출처 주소는 저장만 하며 서버가 원문·사실 여부를 확인하지 않습니다. 미정 맛·경험·결론은 `[실제 맛 반응]`, `[고른 실제 이유]`, `[시식 후 결정]`처럼 남깁니다. 타이머·유행·순위·한정·추천을 만들어 넣지 않습니다.
4. 확정 대본을 입력하면 문구·숫자·줄바꿈을 그대로 보존하고 그 멘트를 장면으로 나눕니다. **대본 합친 버전**은 장면의 멘트와 동일합니다. 문구 검토는 수정 제안만 하고, 클릭한 제안이나 직접 편집만 반영합니다. 멘트와 동일한 장면 자막 아이디어는 명시적 멘트 수정 시 함께 갱신합니다. 독립적으로 작성한 자막은 보존합니다.
5. 각 장면에 **실제 원본·시작/종료 시간**을 연결하고 **편집본 구성**을 누릅니다. 연결한 실제 구간 순서로 타임라인을 바꾸며 취소/다시 실행을 지원합니다. 예상 목표 길이와 실제 연결 길이를 별도로 표시합니다. 목표에 맞춰 원음을 빠르게 만들거나 대사를 자동 삭제하지 않습니다.
6. 실제 촬영·녹음은 필요합니다. 기획 대본을 자동 합성 음성으로 만들거나 원본에서 말하지 않은 내용을 인식 자막에 넣지 않습니다. 컷 편집 후 아래 자막 검수와 출력 과정을 진행합니다. 기획서는 Markdown으로 저장할 수 있습니다.

## 자막·기획 문구 오타 검수

- 인식은 한국어 고정, beam 5, 단어 시간·신뢰값, 무음 환각 억제 설정을 사용합니다. 제품명·브랜드를 **컷 설정의 제품명 필드**에 입력하면 인식 힌트로 사용합니다. 참고 대본은 원문 대조용이며 인식 결과에 강제로 넣지 않습니다.
- **수정 사전**에 `잘못 인식한 표기 => 확인한 표기`를 한 줄씩 등록합니다. 자막의 **문구 검토** 또는 기획 보드의 **대본·제목·캡션 검토**에서 등록 표기와 일부 맞춤법 규칙의 제안을 보여줍니다. 모든 한국어 문법·맞춤법·사실 오류를 찾는 범용 교정기가 아닙니다.
- 숫자·점수·부정 표현·미정 빈칸·미확인 인기 주장을 검토 대상으로 표시합니다. 인식 원문과 편집한 문구를 함께 보고 **원음 대조/앞뒤 재생**으로 실제 발화를 확인하세요. 인식 신뢰값은 정확도 보장이 아닙니다.
- 자막마다 **검수 완료**를 누른 후 최종 MP4/SRT를 출력합니다. 미검수 자막이나 미정 빈칸이 있으면 서버가 최종 출력과 SRT 다운로드를 거부합니다. 문구·시간·인식 원문이 바뀌면 검수 상태가 무효가 됩니다. 검수 전 렌더 미리보기는 허용합니다.
- 재생성은 같은 원본 단어 범위의 수정 문구를 유지합니다. 분절·수동 추가 등으로 대응하지 못한 문구는 **이전 수정 자막**에 보관해 복사할 수 있습니다. 다른 단어 범위에 임의로 적용하지 않습니다.

## 작업 흐름

1. 촬영 파일을 올리면 프로젝트가 자동 생성됩니다. 파일 여러 개와 기존 프로젝트 선택도 지원합니다. 8MiB 청크로 전송하고 SHA-256을 검증합니다. 중단 후 같은 파일을 다시 선택하면 기존 청크 내용을 확인하고 이어올립니다.
2. 첫 화면의 **무음 자동 편집 시작**을 누릅니다. 실제 소리 크기가 기본 −40dB 이하로 0.6초 이상인 구간을 찾고, 소리 앞 0.12초/뒤 0.2초를 남겨 타임라인에 바로 적용합니다. 음식 소리·음악을 대사 부재만으로 삭제하지 않습니다. 자막 모델 없이 사용할 수 있습니다. 감도와 여유 시간은 조절할 수 있습니다. 컷 적용 → 실제 미리보기 MP4 생성까지 자동이며 원본/편집 길이와 삭제 시간이 표시됩니다.
3. 로컬 장면 분석의 제품·시식·단면·조리 후보는 무음 삭제에서 보존합니다. 추가로 남길 부분은 수동 보존 구간으로 지정합니다. **편집본 처음부터 재생**으로 확인하고 **고화질 MP4 저장 → 편집본 MP4 다운로드**로 받습니다. 자동 편집 직후 **자동 편집 되돌리기**로 이전 타임라인을 복원할 수 있습니다. 후보 적용은 보호 구간을 제외하며 개별 공백도 복원할 수 있습니다. 타임라인에서 원본 시작/종료·제품명을 수정하고 분리·합치기·복제·순서를 조절할 수 있습니다. 취소/다시 실행은 현재 프로젝트를 연 브라우저 세션에서 최대 40단계입니다.
4. 화면 설정에서 전체 보이기/단색, 전체 보이기/흐린 배경, 직접 크롭을 선택합니다. 9:16 원본의 기본 전체 보이기는 불필요하게 확대하지 않습니다. 위치·확대율을 구간별 또는 전체에 적용합니다.
5. 자막이 필요하면 컷 설정에서 **자막용 음성 인식**을 실행한 뒤 편집본 기준 자막을 생성하고 문구·시간을 수정합니다. 나누기·합치기·자막만 삭제·수동 추가·SRT 다운로드를 지원합니다. 경계에 걸친 인식 단어와 짧거나 긴 자막은 검토 대상으로 표시합니다. 제품명·참고 대본은 메모로도 보관하며 실제 말하지 않은 문장을 추가하지 않습니다.
6. 전체/제품별/컷별로 자막 없는 MP4와 별도 SRT를 출력합니다. ZIP에 참고·복원용 편집 목록도 들어갑니다. 합본의 컷이 캡컷 편집 클립으로 자동 복원되지는 않습니다.

## 제한과 저장 방식

- 입력은 **파일당 10GB = 10,000,000,000바이트**, 영상 **최대 7,200초**입니다. 원본 검사는 실제 ffprobe 메타데이터로 수행합니다.
- 출력은 **영상당 최대 1,800초**입니다. 전체가 넘으면 구간을 줄이거나 제품/컷별로 출력하세요. 내용·속도를 자동 변경하지 않습니다.
- 원본·청크 완료 상태·편집·작업 상태·분석 체크포인트·출력은 `.data`에 저장합니다. 원본 영상은 별도로 유지합니다. 업로드 중인 파일의 삭제와 출력 정리를 구분합니다.
- 프레임 경계는 30/60fps 격자에 정규화합니다. 미리보기·렌더·SRT는 같은 편집 타임라인을 사용합니다. 렌더에는 편집 버전 스냅샷을 저장하고 이후 변경과 분리합니다. 최신 자막과 다른 컷 타임라인을 묶어 내보내지 않습니다.
- 자막 문구만 수정하면 SRT만 다시 다운로드할 수 있으며 영상 렌더는 필요하지 않습니다. 컷 변경 후 자동 재생성 시 같은 원본 단어 범위의 수정 문구를 유지합니다. 대응하지 못한 수동 수정 문구는 이전 수정 자막 보관함에 남기며 출력에 자동 삽입하지 않습니다. 변경 후 검수 상태를 확인하세요.
- 편집본 기본 출력은 H.264/AAC, 1080×1920, 30/60fps, 48kHz 스테레오입니다. 영상에 자막·가이드·워터마크를 넣지 않습니다. PQ/HLG는 SDR 톤 매핑을 적용합니다. Dolby Vision 동적 메타데이터는 지원하지 않습니다.
- 화면의 원본 기반 미리보기는 빠른 구간 확인용입니다. 브라우저별 HDR 표시와 크롭 근사에 차이가 있습니다. **렌더 미리보기**는 최종 출력과 같은 FFmpeg 필터를 써서 컷·화면·색 변환을 확인합니다. 최종 출력은 프리뷰 파일을 재사용하지 않습니다.
- ZIP64를 사용하고 ZIP_STORED로 영상 재압축을 피합니다. 청크·FFmpeg·결합·ZIP·다운로드 경로에서 원본/출력 전체를 메모리에 올리지 않습니다.
- 작업 큐는 서버 내 단일 워커입니다. **uvicorn 프로세스는 반드시 1개**로 실행하세요. DB·파일락을 통해 중복 워커를 거부합니다. 앱은 큰 파일을 다루므로 CPU·디스크가 있는 서버와 영속 볼륨이 필요합니다. 서버리스의 짧은 요청 제한 환경에 그대로 배포하는 구조가 아닙니다.
- 요청 타임아웃과 미디어 작업 제한은 별개입니다. `STUDIO_JOB_TIMEOUT_SECONDS` 기본 86,400초는 각 FFmpeg 호출의 실행 한도이고, Whisper는 120초 윈도 사이/인식 세그먼트마다 취소를 확인합니다. 분석/렌더 전체의 종료 시각을 보장하는 하드 타임아웃은 아닙니다.
- 재시작하면 처리 중 작업을 재개하고 완료 분석 윈도·렌더 조각을 재사용합니다. 명시적으로 취소하면 작업 임시 파일을 정리합니다. 실패한 작업은 체크포인트를 보존해 재시도할 수 있습니다.

10GB 원본·중간 조각·최종 출력·ZIP이 함께 존재하므로 운영용 저장 공간은 **100GB 이상을 권장**합니다. 입력 업로드와 출력 시작 시 여유 공간을 검사하며, 출력의 보수적인 비트레이트 예산에 따라 공간이 부족하면 시작을 거부합니다. 이 개발 환경의 공간은 약 32GB이므로 최대 입력과 여러 긴 출력의 동시 보관을 보장하지 않습니다.

## 배포 구성

공개 서버용 자동 HTTPS·영속 저장소·릴리스별 재배포·이전 이미지 복원 구성은 [deploy/README.md](deploy/README.md)에 있습니다. 실제 서버·호스팅과 도메인 연결이 필요하며, 현재 공개 배포는 수행하지 않았습니다.

`Dockerfile`, `deploy/compose.yaml`, `deploy/nginx.conf.example`에 실행 예시를 제공했습니다. Docker 이미지 빌드와 단일 컨테이너 기능 검증 결과는 `VALIDATION.md`에 기록합니다. HTTPS 프록시·운영 도메인 배포는 별도입니다.

```bash
# STUDIO_PASSWORD를 운영 환경의 안전한 설정에 먼저 지정합니다.
docker compose -f deploy/compose.yaml up -d --build
docker compose -f deploy/compose.yaml exec studio python scripts/download_model.py --model medium
```

Docker 모델은 영속 `/data`에 저장합니다. 운영 호스트의 TLS/도메인/영속 볼륨/CPU/디스크를 준비하세요. 프록시 예시는 8MiB 청크에 맞춰 요청 한도를 9MiB로 두고 작업은 HTTP 요청과 분리합니다. 앱 내부 요청 검증은 더 엄격한 8MiB입니다. 전달 헤더는 신뢰하는 프록시에서만 받아야 하며 앱 포트를 외부에 직접 노출하지 마세요.

이 클라우드 환경처럼 네트워크 프록시와 별도 CA 신뢰가 필요한 빌드는 `bash scripts/docker_build.sh`를 사용합니다. 이 스크립트는 기존 프록시를 표준 BuildKit 인자로 전달하고 제공된 CA 번들을 읽기 전용 빌드 secret으로 사용합니다. TLS·패키지 서명 검증을 끄지 않으며 CA 번들을 이미지에 저장하지 않습니다. 빌드한 뒤 `docker compose -f deploy/compose.yaml up -d --no-build`로 사용할 수 있습니다. Docker 설정 캐시는 `.data/docker`에 저장됩니다.

기존 `iyoring-cut-studio.alis314.chatgpt.site`에 게시하거나 기존 원본을 마이그레이션하지 않았습니다. 해당 Sites 프로젝트의 서버 지원·소스·배포 도구가 없어 동일 주소 배포는 별도 연결 작업이 필요합니다.

## 검증

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/make_sample.py /tmp/iyoring-sample.mp4
# 서버가 실행되고 Playwright와 Chromium이 설치된 환경에서:
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/browser_smoke.py
.venv/bin/python scripts/browser_planning_smoke.py
```

자동 검증과 실제 실행 결과는 `VALIDATION.md`를 참고하세요. 희소 10GB 파일과 저밀도 2시간 영상 테스트는 실제 10GB 촬영 원본의 부하 테스트와 다릅니다. 작은 샘플 성공으로 장시간 최대 용량의 안정성을 보장하지 않습니다.

검증용 원문이 있는 짧은 한국어 녹음은 다음 명령으로 모델별 인식 문구와 공백·문장부호 제외 문자 오류율을 비교할 수 있습니다. 해당 모델은 먼저 다운로드해야 합니다. `--vocabulary`로 확인된 제품명을 전달할 수 있습니다. 이 도구는 120초 이하 영상으로 제한합니다.

```bash
.venv/bin/python scripts/check_transcription.py sample.mp4 verified-transcript.txt --models medium --vocabulary '확인한 제품명'
```

이 클라우드의 Docker는 vfs 저장 드라이버라 반복 빌드의 실제 디스크 점유가 이미지 표시 크기보다 커질 수 있습니다. 빌드 전 여유 공간을 확인하고 이 앱의 사용하지 않는 이전 이미지·빌드 캐시를 구분해 정리하세요. 원본·프로젝트를 보관한 `.data` 전체를 삭제하지 마세요. 개발 환경에서 발생한 공간 부족과 복구 기록은 `VALIDATION.md`에 남겼습니다.

사용자가 지정한 공개 배포 대상은 기존 `iyoring-cut-studio.alis314.chatgpt.site`입니다. 현재 대화의 도구에는 해당 사이트의 편집·게시 기능이 없어 게시하지 않았습니다. 다른 호스팅이나 임시 공개 주소로 대신 게시하지 않았습니다.

새 공유 대화에서 기존 Sites 앱의 브라우저 처리 구조와 개발 환경 접근 문제를 확인했습니다. 서버 처리 구조의 이번 앱을 해당 Sites에 그대로 배포할 수 있다고 확인하지 않았습니다. 프로젝트 정보·구조 차이·지원 요청 안내는 [SITES_HANDOFF.md](SITES_HANDOFF.md)를 참고하세요.

새 호스팅 테스트용 파일은 [deploy/huggingface/SETUP.md](deploy/huggingface/SETUP.md)를 참고하세요. 현재 공식 안내의 유료 플랜 조건을 포함했으며 실제 계정 게시는 수행하지 않았습니다.
